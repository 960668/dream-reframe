# 梦境重构 · Dream Reframe

> 把一段醒来后即将遗忘的梦，重构成可读的故事分镜，和一组可以直接喂给文生图模型的视觉提示词。

![首屏](assets/shot-hero.png)

## 这是什么

你刚醒来，脑子里还残留着一些画面：会呼吸的书架、退潮的瓷砖地、一道没有尽头的玻璃楼梯。你随手把它打出来——顺序是乱的，因果是缺的，五分钟之后它就会消失。

**梦境重构**不解释这个梦意味着什么，它做三件事：

1. **解析**：从混乱的口述里抽出核心意象、情绪基调、关键场景
2. **分镜**：把这些素材重新剪辑成 4 个镜头，每个镜头有画面、情绪和运镜
3. **视觉化**：为每个镜头写一段英文提示词，并生成一条统一的**风格锚点**，保证四张图看起来像同一部片子

输出可以一键复制到 Midjourney / 即梦 / Stable Diffusion，也可以导出为 JSON 留档。

## 快速开始

不需要安装任何依赖，只要 Node 18+。

```bash
git clone https://github.com/<你的用户名>/dream-reframe.git
cd dream-reframe
node server.mjs        # 或者 npm start
```

打开 <http://127.0.0.1:8080>：

1. 展开「模型设置」，选服务商（DeepSeek / 智谱 / Kimi / 通义 / 硅基流动 / OpenAI，或任意 OpenAI 兼容接口）
2. 粘贴你的 API Key，保存
3. 描述一个梦，点「重构这个梦」

没有 Key 也能玩：点「看示例效果」可以走完整个交互流程（页面会明确标注这是示例数据）。

## 关于密钥

- 应用**不内置任何密钥**，也不会把你的 Key 发到除模型服务商以外的任何地方
- Key 只存在你这台设备的浏览器 `localStorage` 里，换浏览器要重填
- 提交到 GitHub 的代码里没有任何密钥，可以放心开源

> 为什么要 `server.mjs`：部分服务商没有开放浏览器跨域（CORS），页面直连会被浏览器拦截。这个零依赖的本地脚本把请求从本机转发出去。如果你的服务商允许直连，页面上「经本地代理转发」不勾选也能用。

## 几个设计取舍

**为什么先出分镜，再出提示词，而不是一口气生成？**
提示词必须建立在稳定的分镜之上。把两步拆开，第二步只需要处理「画面语言」，第一次的失误不会污染第二次的结果，也更容易定位是哪一步出了问题。

**为什么解析和分镜合并成一次调用？**
它们共享同一份上下文，拆开只会多付一次延迟和一次输入 token，换不到质量提升。分镜之后才拆，因为视觉提示词需要的是结构化结果，而不是自然语言。

**为什么要「风格锚点」？**
跨镜头一致性是文生图最难的问题之一。把媒介、色调、光线、镜头语言固定成一条字符串，拼进每个镜头的提示词，是成本最低、效果最稳的做法。

**为什么模型输出走 `textContent`，不走 `innerHTML`？**
模型输出是不可信输入。它可能包含被诱导出的 HTML，直接插入就是 XSS。这条线在代码里是硬约束。

## 局限

- 生成的只是提示词，不直接出图——因为浏览器端直连文生图接口需要暴露密钥，正确做法需要一个服务端，见 Roadmap
- 没有「重生成单个镜头」——目前只能整体重来
- 梦境记录不做云端留存，这是一次性的工具，不是档案库

## 发布到 GitHub

```bash
cd dream-reframe
git init
git add .
git commit -m "init: dream-reframe v0.1"

# 在 GitHub 上新建一个空仓库（不要勾选自动生成 README）
git remote add origin git@github.com:<你的用户名>/dream-reframe.git
git branch -M main
git push -u origin main
```

推上去之后记得做两件事：

1. 把 `src/config.js` 里的 `REPO_URL` 改成你的仓库地址，页脚链接才会生效
2. 在仓库 About 里填一句话简介，并把 `assets/shot-result.png` 设为 social preview
