# 梦境重构 · 产品说明（PRD）

## 一句话定位

把醒来后五分钟内就会蒸发的梦境，凝固成一份可读、可分享、可继续创作的资产。

## 问题

梦的素材是独一无二的，但它的保存窗口极短。复述一个梦时人通常得到的是一团语无伦次的碎片：跳跃的场景、断裂的时间线、说不清的情绪。大多数人因此干脆不记——于是那些真正有趣的素材每天都在流失。

市面上已有的解法大多不成立：

- **解梦类产品**：急于给出象征意义的解释。但解释是主观的、廉价的，而且会替代掉梦本身的价值。
- **日记类产品**：只负责存储，不负责加工。存下来的还是那团碎片，三个月后你自己都不会再看。

## 我们的选择

**不做解梦，做剪辑。**

梦不需要被解释，它需要被重新组织成一个能被别人看懂的东西。所以产品的输出不是「这个梦代表你内心的焦虑」，而是：一个标题、一段概括、几个画面、一组可直接使用的视觉提示词。

这个定位同时解决了三件事：

1. **可读性** —— 画面是有秩序的，别人能看懂
2. **可分享性** —— 配上画面，它就变成一条可以发出去的内容
3. **可创作性** —— 提示词让梦的素材能继续进入创作流程

## 核心链路

```
梦境口述 ──► AI 结构化（意象 / 情绪 / 场景）
        ──► 画面重构（2-5 个画面：画面 / 情绪 / 身体感）
        ──► 视觉提示词（每个画面一段英文提示词 + 统一风格锚点）
        ──► 出图（可选：免费文生图模型，单张可重生成）
        ──► 输出（图片 + 提示词 / 复制 / 导出 JSON）
```

## 关键产品决策

### 1. 不做解梦

这是整个产品的立场。解梦会替用户下结论，而结论会关掉想象的空间。我们只重组，不解读。这条原则写进了系统提示词的第一段。

### 2. 用梦的语法，不用电影的语法

这是 v0.1 之后最重要的一次修正。

最初的版本让模型输出「景别 + 运镜」，结果是每一份重构读起来都像奇幻短片，不像梦。复盘后发现问题不在措辞，而在**语法本身就是错的**：分镜、景别、运镜是导演的组织方式，把体验拆成机位、景别、剪辑点；而梦的组织方式是画面之间的**无过渡跳接**，以及身体感的持续在场。你醒来后记得的不是「低角度仰拍」，是「水在退，但脚是干的」。

改法有两步：

- 画面字段从 `camera`（运镜）换成 `sensation`（身体感：触感、温度、声音、失重或沉重）
- 构图推迟到第二段，由模型根据画面内容自行决定；视角则固定为第一人称——这是唯一值得写死的「机位」，理由见决策 10

更关键的教训是：**只有负向约束是不够的。** 最初我们写了「不要解梦」「不要引入新意象」，但从未正面告诉模型「梦的语法是什么」。缺了这一层，模型会自动退回它最熟悉的模式——一条正常叙事线加几个奇怪道具。所以现在系统提示词里明确列出了六条梦的运作方式：场景无过渡切换、物理不成立、身份漂移、情绪与画面错配、清晰度不均匀、不给梦一个结局。

### 3. 画面先行，提示词在后

视觉提示词必须建立在稳定的画面结构之上。如果直接从口述一步跳到提示词，错误会在链条末端才暴露，且无法定位是哪一步引入的。拆成两步之后，第二步只需要处理画面语言，质量与可调试性都更高。

### 4. 解析与画面编排合并为一次调用

两者共享同一份上下文，拆开只增加延迟与 token 成本，换不到质量。画面之后才拆，因为视觉提示词消费的是结构化结果，而不是自然语言。

### 5. 风格锚点解决跨画面一致性

跨画面一致是文生图最难的问题之一。解法是先生成一条统一的风格描述（媒介、色调、光线、质感、画幅），拼进每个画面的提示词。成本最低、效果最稳，也给了用户一个可手动微调的入口。

锚点的引导方向刻意定在「梦境质感」而不是「电影质感」：优先颗粒感、柔焦与超清晰并存、轻微透视畸变、来处不明的光源、单一颜色过饱和、边缘溶解、暗部不黑；避开干净考究的影棚感。

### 6. 不修正梦里的不成立

文生图模型有强烈的合理化倾向：它会自动把「水面高于地面」画成正常的水边风景。所以视觉提示词的规则里明确要求——不成立的地方照写，不许修正。

### 7. 尊重原料

系统提示词里最硬的一条规则：所有意象必须来自用户原文，可以重组顺序、补全感官细节，但不允许引入原文没有的核心意象。梦是用户的私产，模型没有权利替用户添加内容。

这条规则和「还原梦的语法」之间的边界必须写清楚，否则模型会以「制造梦境感」为名编造意象。提示词里对此有单独的兜底句：以上是还原方式，不是添加内容的许可。

### 8. 密钥不进代码，数据不出设备

应用不内置任何密钥，用户填自己的 OpenAI 兼容接口；配置只存在浏览器本地。这让项目可以完全开源，也让信任边界非常清晰。

### 9. 出图是可选的一步，不是链路的终点

v0.1 只出提示词，v0.2 加了出图。加的时候刻意守住了三条边界：

- **可选**：文字链路完整独立。用户可能只想拿提示词去 Midjourney——提示词本身就该是完整交付物，出图是锦上添花，不是依赖项。
- **串行**：免费出图模型普遍有并发限制，并行发四张的结果是四张一起被限流。串行慢一点，但稳定拿到图。
- **可局部重来**：单张失败（限流、内容审核）不中断整批，失败的画面写明原因、单独重试。整批作废是对免费额度的浪费。

另一个实测后修正的假设：原以为浏览器出图必须经服务端代理（为了藏密钥）。实测发现主流国内服务商都允许浏览器跨域直连，而本项目本来就是把密钥交给用户自己填、存浏览器本地——所以纯前端方案成立，服务端这层依赖被整个砍掉了。

### 10. 视角固定第一人称，人脸不可辨认

这是对决策 2 的一次**刻意例外**。

决策 2 的立场是「梦里没有机位」，所以视角不写死。但第一人称是唯一值得写死的那个机位——它不是导演的选择，而是「正在经历」这件事本身。梦的记忆本来就是从自己眼睛看出去的；用第三人称叙述会把用户从梦里推出去，变成一个旁观者。

同一条决策里还有第二件事：**不出现可辨认的人脸**。两个原因——跨画面的人物面部一致性靠提示词根本做不到（见「明确不做的」），躲开正脸比硬碰更划算；而且脸一旦清晰，人就会开始辨认「这是谁」，梦的匿名感立刻消失。

落地方式分三层，而不是只写在一条提示词里：

| 层 | 位置 | 写成什么 |
|---|---|---|
| 文字层 | `ANALYZE_SYSTEM` 的「视角与人物」 | 第一人称叙述；需要有人时用背影、侧影、遮挡、失焦 |
| 画面层 | `VISUAL_SYSTEM` 规则 4、5 | 每条英文提示词都写明 `first-person view` 与人物写法 |
| 出图层 | `IMAGE_GUARD` / `IMAGE_NEGATIVE` | 正向写「脸在画外或模糊到不可辨认」，负向排除 `close-up portrait`、`third-person view` |

为什么不能只写一层：文生图模型看不到中文那一层，语言模型也管不到最终出图。三层各管一段，缺一层就会漏。

## 明确不做的

- 不做心理分析、不输出任何「代表」「暗示」类结论
- 不做云端存储（v0.3 之前），梦境是一次性工具的输入，不是档案库的记录
- 不做跨画面的人物面部一致性（LoRA / 参考图级别）——目前靠提示词级别的风格锚点，人脸一致性没有保证

## 目前的局限

- 出图只能用允许浏览器直连的服务商（主流国内厂商都支持；OpenAI 不支持）
- 无法单独重生成某个画面的**文案**（图片已经可以单张重生成）
- 没有「梦境库」，梦做完就散了
- 「梦境感」目前只靠提示词约束，没有评测集来量化——无法回答「这次改动到底让它更像梦了吗」
